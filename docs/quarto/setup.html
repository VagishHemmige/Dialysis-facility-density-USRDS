Packages

Each data source has an access package: usRds for the USRDS files and the CMS facility snapshots, tidycensus for the American Community Survey. flowchart builds the cohort, so the STROBE diagram and the analytic data come from the same code. glmmTMB fits the mixed-effects logistic models and lme4 the linear ones, gtsummary and gt build the tables, and mice imputes albumin and hemoglobin.

Cohort constants

These implement section 4 of the analysis plan. dialysis_settings_kept keeps in-center dialysis only, which excludes home dialysis as the paper says. The original code did the same by keeping DIALSET codes 1 and 2, but the coding has changed since: in the current USRDS coding, code 1 is home, so the setting is now named rather than numbered. The eGFR restriction (20 or below) and the outcome (early means 10 or above) also follow the original code, where the paper’s text says “less than 20” and “greater than 10”; the two differ only for patients at exactly 20 or exactly 10.

Click to show/hide R Code 
# Cohort (analysis-plan.md section 4): years in which dialysis started
study_years <- 2011:2019
minimum_age <- 18

# Dialysis setting kept: in-center dialysis only, as the paper says (home
# dialysis excluded). The coding of DIALSET has changed. The original code kept
# codes 1 and 2 to exclude home dialysis, which was correct for the earlier
# coding (Appendix C format $MESET_CUR: 1 = hospital inpatient, 2 = dialysis
# facility/center, 3 = home). In the current coding ($MESET, 2024 Researcher's
# Guide) 1 = home and 2 = dialysis facility/center, so the same intent now
# keeps code 2 only. usRds labels the codes, so the setting is named here.
# (Decided by Vagish Hemmige, 27 October 2026.)
dialysis_settings_kept <- "DIALYSIS FACILITY/CENTER"

# eGFR restriction (mL/min/1.73 m2): 20 or below, as in the original code
# (the paper says "less than 20"; decided 27 October 2026)
egfr_maximum <- 20

# Outcome (section 7): early initiation is eGFR of 10 or above, as in the
# original code (the paper says "greater than 10"; decided 27 October 2026)
early_egfr_threshold <- 10

# Sensitivity analysis: eGFR range from the original code (exclusive bounds)
sensitivity_egfr_range <- c(5, 25)

# States outside the 48 contiguous states + DC; territories have no region
noncontiguous_states <- c("ALASKA", "HAWAII")

Exposure constants

Density is facilities per 100,000 HSA residents, cut at the 25th, 50th and 75th percentiles of density among patients in the final cohort, as in the original code. The cut points are computed from the data, never typed in; the published ones (1.36, 1.95 and 2.76) appear only in a comment in define_exposure.R, for comparison.

Click to show/hide R Code 
# Exposure (section 5): facilities per this many HSA residents
density_per_population <- 100000
# Cut points: these percentiles of density among patients in the final cohort
density_percentiles <- c(0.25, 0.50, 0.75)

Linkage constants

Each ACS variable carries a pattern its label must match in every year. Subject-table codes such as S0601_C01_047 can mean different things in different years, and the original code assumed they did not; now a mismatch stops the run. Dartmouth’s -88888 and -99999 are codes for small or suppressed values, not numbers, so they become missing. The RUCA groups give the four rural-urban types in the paper’s Table 1.

Cause of kidney failure

The six categories are those of the paper’s Table 1. The mapping of every USRDS code to a category is drafted by three cloud models, one each from OpenAI, Anthropic and Google, each provider’s current general-purpose model as of October 2026. Codes on which at least two agree are accepted, and the deciders review the rest. Two models run locally through Ollama (Alibaba’s Qwen and Meta’s Llama) answer too and are reported for comparison, without voting (esrd_classifier_voting lists the voting models). Gemini and Qwen get batches of 25 codes rather than 100, and Llama batches of 5 (see Classifying codes; open decision D4). The models used, the prompt version and the ellmer version are recorded in the output file.

Click to show/hide R Code 
# Primary cause of kidney failure (section 6). The mapping of every $PD96DET code
# is in references/esrd-cause-categories.csv (open decision #D4).
esrd_cause_categories <- c(
  "Diabetes",
  "Hypertension and cardiac disease",
  "Glomerulonephritis",
  "Hereditary or polycystic kidney disease",
  "Transplant failure or complications",
  "Other"
)
esrd_cause_mapping_file <- "references/esrd-cause-categories.csv"
# One row: how many codes the models agreed on, and Fleiss' kappa
esrd_cause_agreement_file <- "references/esrd-cause-agreement.csv"
# One row per local model: how complete and valid its answers were, and how
# often it agreed with the accepted category (reported, not used to accept)
esrd_local_model_file <- "references/esrd-cause-local-models.csv"

# Models used by R/classify_esrd_causes.R. Three cloud models, each
# provider's current general-purpose model as of October 2026, as in an
# earlier ensemble by the same team (gpt-5.1, claude-sonnet-4-5,
# gemini-2.5-flash); and two local models run through Ollama on the analyst's
# own computer, which send nothing over the internet: Alibaba's Qwen and
# Meta's Llama, from two further companies (decided by Vagish Hemmige, 28 and
# 29 October 2026). Llama 3.1 replaced IBM's Granite (granite4.2:8b) on 29
# October 2026: on the analyst's laptop Granite returned no answers for 5
# codes in 15 minutes. Qwen answers with its "thinking" turned off: with it
# on, its reasoning filled Ollama's working space before the answer was
# written. (Ollama's medical models are all Google's MedGemma, which would
# overlap with Gemini, or older models built on Llama 2.) Change a name here
# to use another model; the models used are recorded in the output.
#
# Only the three cloud models vote. The local models are run and reported
# for comparison, but do not vote (decided by Vagish Hemmige, 29 October
# 2026): on the analyst's laptop neither produced a complete, valid set of
# answers. Both left codes unanswered, returned text that is not a code (a
# code in quotation marks, "</code>" fragments, web addresses, codes not in
# the list) and gave categories that contradict their own reasons.
esrd_classifier_models <- list(
  openai = "gpt-6.1-terra",
  anthropic = "claude-sonnet-5-5",
  google = "gemini-3.8-flash",
  ollama_qwen = "qwen3.5:9b",
  ollama_llama = "llama3.1:8b"
)
esrd_classifier_voting <- c("openai", "anthropic", "google")
# Codes sent per call. Gemini timed out on batches of 100, and local models
# are slower and handle less text at once, so they get smaller batches. On the
# analyst's laptop, Llama 3.1 answered only 7 of a batch of 25 codes but all of
# a batch of 5 (29 October 2026)
esrd_classifier_batch_sizes <- list(
  openai = 100,
  anthropic = 100,
  google = 25,
  ollama_qwen = 25,
  ollama_llama = 5
)
# A category is accepted when at least this many of the three voting models
# give it: 2 of 3, a majority (decided by Vagish Hemmige, 29 October 2026,
# when the local models stopped voting; the rule had been 3 of 5). Other codes
# go to the deciders.
esrd_classifier_min_agreement <- 2
esrd_classifier_prompt_file <- "prompts/esrd-cause-classification.md"
# Output limit for Claude. ellmer 0.5.0 caps Claude's answers at 4,096 tokens
# unless told otherwise, too few for a batch of 100 codes with reasons; the
# other providers have no default cap in ellmer.
esrd_classifier_claude_max_tokens <- 16000
# Seconds to wait for one answer. ellmer's default, 5 minutes, is too short
# for a local model on a laptop processor; the cloud models answer well within
# either limit.
esrd_classifier_timeout_s <- 30 * 60
# Each provider's checked answers are saved here (gitignored), so a rerun does
# not pay for a provider that already finished
esrd_votes_dir <- file.path(public_data_dir, "esrd-cause-votes")

Model constants

The covariate sets follow the footnotes of the paper’s Table 2, and Model 3’s HSA benchmarks are the three the paper’s Methods name. The logistic models are fit with glmmTMB (Laplace approximation); the models page explains why.

Click to show/hide R Code 
# Mixed-effects logistic models (section 8) are fit with glmmTMB, using the
# Laplace approximation. On synthetic data shaped like Model 3, lme4::glmer
# needed rescaled covariates and a higher iteration limit to converge and took
# about 30 times longer, for the same estimates; adaptive quadrature with 7
# points (Stata's default) changed the odds ratios only in the third decimal
# (decided by Vagish Hemmige, 27 October 2026).
imputation_count <- 10
imputation_seed <- 20231020

# Covariates added at each step of Table 2 (section 8), from the Table 2
# footnotes; the HSA benchmarks are the three the Methods name
# Year of hemodialysis initiation, as the paper's Methods say; the original R
# code used the year of the form (decided 27 October 2026)
model_1_covariates <- c("age", "sex", "race", "hispanic", "dialysis_year")
model_2_covariates <- c(model_1_covariates,
                        "heart_failure", "coronary_disease", "diabetes",
                        "cerebrovascular_disease", "alcohol_or_drug", "immobility",
                        "institutionalized", "access_type", "esrd_cause")
model_2_laboratory <- c("albumin", "hemoglobin")
model_3_covariates <- c(model_2_covariates,
                        "insurance", "nephrology_care", "rural_urban",
                        "zip_percent_poverty", "zip_percent_black",
                        "hsa_ambulatory_sensitive_discharges",
                        "hsa_percent_eye_exam", "hsa_percent_hba1c")
