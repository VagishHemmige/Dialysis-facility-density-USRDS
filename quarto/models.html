    mixed_formula("early_start", exposure, covariates),
    data = data,
    family = binomial
  )

model_covariates <- function(model, labs, patients) {
  covariates <- switch(
    model,
    "Model 1" = model_1_covariates,
    "Model 2" = model_2_covariates,
    "Model 3" = model_3_covariates

Models

Mixed-effects models with a random intercept for HSA, progressively adjusted, fit with glmmTMB (Brooks et al. 2017): logistic for early start, linear for eGFR. With albumin and hemoglobin, patients missing either value drop out of Models 2 and 3, as in the paper’s complete-case models. The covariates follow the paper’s Table 2 footnotes; the “HSA quality benchmarks” in Model 3 are taken to be the three the paper’s Methods give as examples (“such as”: HbA1c testing and eye examinations among enrollees with diabetes, and ambulatory-sensitive discharges).

Choosing the model-fitting package

The paper fit its models in Stata 15 and calls them mixed-effects logit models; it does not name the command. If they were fit with melogit, Stata’s default is adaptive Gauss-Hermite quadrature with 7 points (StataCorp, n.d.).

A mixed model’s likelihood has to be computed by approximation, because each HSA’s random effect is averaged over. The Laplace approximation does this with one point per HSA; adaptive quadrature uses several (here 7), which is more exact but slower. When each HSA has many patients, as here, the two give practically the same answer. In R there are several ways to fit the same model. On synthetic data shaped like Model 3 (4,000 patients, 60 HSAs, about 40 covariate terms), they compared as follows:

Fit Time Convergence warnings Odds ratio, highest vs zero density
lme4::glmer (Bates et al. 2015), default settings 117 s 4 10.08 (not converged)
lme4::glmer, rescaled covariates, higher iteration limit 111 s 0 10.62
lme4::glmer, 7-point quadrature (Stata’s default) 119 s 0 10.63
glmmTMB (Brooks et al. 2017) 4 s 0 10.63

The numbers are synthetic; only the comparison matters. glmmTMB gave the same estimates as a fully converged glmer in about a thirtieth of the time, without rescaling, and quadrature with 7 points rather than the Laplace approximation changed the odds ratios only in the third decimal, because each HSA has many patients. The analysis therefore uses glmmTMB (decided by Vagish Hemmige, 27 October 2026). Three other options were considered:

  • GLMMadaptive fits the model with adaptive quadrature and any number of points, closest to Stata’s method. It was not timed here.
  • MixedModels.jl (Alday and Bates, n.d.), a Julia package by Douglas Bates, the original author of lme4, and Phillip Alday, is designed for very large models and can be called from R with the jlme package (Choe 2024). It needs a Julia installation, and jlme is a young, single-maintainer package with little recent activity, so it was not used.
  • Stata itself, called from R. The RStata package (Braglia 2025) runs Stata commands or a do-file from R and passes a data frame in and out, for example stata("melogit early_start i.density_category ... || hsanum:", data.in = model_data); Stata 17 and later also offer pystata, Stata’s own interface, which R can reach through reticulate. This would keep the paper’s estimation method, if the paper used melogit with its default 7-point adaptive quadrature, but it needs a Stata licence, so it is not part of the public code. Neither Stata nor MixedModels.jl was timed here, so how their speed compares with each other or with glmmTMB on these data is not known.

Multiple imputation

The paper reports “a multiple imputation technique with chained predictive analytics (10 imputations)” for albumin and hemoglobin (eTable 2), done in Stata, read here as chained equations; it gives no other detail, and the original R code has none. Here only albumin and hemoglobin are imputed, by predictive mean matching (the mice default for numeric variables (Buuren and Groothuis-Oudshoorn 2011)), from the outcome, the density category and the Model 3 covariates. HSA is not a predictor (about 3,400 levels), and continuous density is not used as a predictor because it duplicates the density category. This imputation model was confirmed by Vagish Hemmige on 28 October 2026 (decision D7).

Fitting

Each distinct model is fit once and its density terms extracted: odds ratios for the logistic models, differences in eGFR for eTable 3, each with a 95% Wald confidence interval. Imputed models are fit on each completed data set and pooled by Rubin’s rules, whose intervals combine the variation within and between the imputed data sets.

Click to show/hide R Code 
# One fit per distinct model; a model that appears in two blocks (Model 1 in
# both blocks of Table 2, for example) is fit once. Logistic models report
# odds ratios; the linear models of eTable 3 report differences in eGFR.
fit_published_model <- function(outcome, exposure, patients, imputed, covariates) {
  # `imputed` (TRUE or FALSE) says whether to use the imputed data sets,
  # imputed_sets
  model_family <- if (outcome == "early_start") binomial() else gaussian()
  formula <- mixed_formula(outcome, exposure, covariates)
  term_pattern <- str_glue("^{exposure}")
  logistic <- outcome == "early_start"

  if (!imputed) {
    fit <- glmmTMB(formula, data = patient_groups[[patients]], family = model_family)
    return(density_effects(fit, term_pattern, exponentiate = logistic))
  }

  # Each completed data set is fitted explicitly and the fits are pooled by
  # Rubin's rules; with(imputed_sets, ...) would not find the variables of a
  # formula built by mixed_formula()
  imputed_sets |>
    mice::complete(action = "all") |>
    map(\(completed) glmmTMB(formula, data = completed, family = model_family)) |>
    as.mira() |>
    pool() |>
    summary(conf.int = TRUE, exponentiate = logistic) |>
    as_tibble() |>
    filter(str_detect(term, term_pattern)) |>
    transmute(
      model = NA_character_,
      term = as.character(term),
      estimate,
      conf_low = `2.5 %`,
      conf_high = `97.5 %`,
      p_value = p.value,
      n = nrow(imputation_data)
    )
}

published_models <- published_models |>
  mutate(fit_key = map_chr(
    transpose(pick(outcome, exposure, patients, imputed, covariates)),
    rlang::hash
  ))

published_fits <- published_models |>
  distinct(fit_key, .keep_all = TRUE) |>
  mutate(result = pmap(
    list(outcome, exposure, patients, imputed, covariates),
    fit_published_model
  )) |>
  select(fit_key, result)

published_estimates <- published_models |>
  left_join(published_fits, by = "fit_key", relationship = "many-to-one") |>
  select(table, block, model, outcome, exposure, result) |>
  unnest(result, names_sep = "_") |>
  select(
    table, block, model, outcome, exposure,
    term = result_term,
    estimate = result_estimate,
    conf_low = result_conf_low,
    conf_high = result_conf_high,
    p_value = result_p_value,
    n = result_n
  )

One model written out

The code above builds every model from the list rather than writing each one out, so no single model appears in it. As an example, this is what it fits for Table 2, Model 3, with albumin and hemoglobin, the paper’s fully adjusted model. Each row of the list becomes a call like this one; the other models drop or add covariates, change the patients, or swap the outcome or exposure.

# Table 2, block "With albumin and hemoglobin", Model 3:
# outcome early_start, exposure density_category, patients "All", labs TRUE
fit <- glmmTMB(
  early_start ~ density_category +
    # Model 1: demographics and year (model_1_covariates)
    age + sex + race + hispanic + dialysis_year +
    # Model 2 adds comorbidities, access and cause (model_2_covariates)
    heart_failure + coronary_disease + diabetes + cerebrovascular_disease +
    alcohol_or_drug + immobility + institutionalized + access_type + esrd_cause +
    # Model 3 adds insurance, nephrology care and area measures (model_3_covariates)
    insurance + nephrology_care + rural_urban + zip_percent_poverty +
    zip_percent_black + hsa_ambulatory_sensitive_discharges +
    hsa_percent_eye_exam + hsa_percent_hba1c +
    # labs = TRUE adds the laboratory values (model_2_laboratory)
    albumin + hemoglobin +
    # random intercept for HSA
    (1 | hsanum),
  data = patient_groups[["All"]],   # model_data: the whole cohort
  family = binomial
)

# The rows reported: odds ratios for the four density categories against
# HSAs with no facility, with 95% CIs, p values and the patients used
density_effects(fit, "^density_category", exponentiate = TRUE)

In the code, model_covariates("Model 3", labs = TRUE, patients = "All") returns these 24 covariates, and mixed_formula() turns them into the formula. A test (tests/test-model-example.R) checks that the formula on this page is the one the code builds, so the example cannot drift from the code.

Variance decomposition

How much of the variation in eGFR at initiation lies between HSAs, and between facilities within HSAs, from two null linear mixed models fit by lme4::lmer with its default, restricted maximum likelihood (REML). The nested model cannot use patients with no dialysis facility ID, so both models are fit on the patients who have one; otherwise the two shares would come from different patients (decided by Vagish Hemmige, 28 October 2026).

Click to show/hide R Code 
# Share of the variance of eGFR at the HSA and facility levels (null models).
# Both models use the same patients, those with a dialysis facility ID, so the
# shares are comparable (decided by Vagish Hemmige, 28 October 2026).
variance_data <- filter(model_data, !is.na(dialysis_provider))

hsa_variance <- lmer(egfr ~ 1 + (1 | hsanum), data = variance_data) |>
  variance_shares() |>
  mutate(model = "HSA")

facility_variance <- lmer(
  egfr ~ 1 + (1 | hsanum / dialysis_provider),
  data = variance_data
) |>
  variance_shares() |>
  mutate(model = "HSA and facility (nested)")

variance_decomposition <- bind_rows(hsa_variance, facility_variance)

|---|---|---|---|
| `lme4::glmer` [@lme4_pkg], default settings | 117 s | 4 | 10.08 (not converged) |

Each row of the list becomes a call like this one; the other models drop or add covariates, change the patients, or swap the outcome or exposure.

```r
# Table 2, block "With albumin and hemoglobin", Model 3:
# outcome early_start, exposure density_category, patients "All", labs TRUE
fit <- glmmTMB(
  early_start ~ density_category +
    # Model 1: demographics and year (model_1_covariates)
    age + sex + race + hispanic + dialysis_year +
    # Model 2 adds comorbidities, access and cause (model_2_covariates)
    heart_failure + coronary_disease + diabetes + cerebrovascular_disease +
    alcohol_or_drug + immobility + institutionalized + access_type + esrd_cause +
    # Model 3 adds insurance, nephrology care and area measures (model_3_covariates)
    insurance + nephrology_care + rural_urban + zip_percent_poverty +
    zip_percent_black + hsa_ambulatory_sensitive_discharges +
    hsa_percent_eye_exam + hsa_percent_hba1c +
    # labs = TRUE adds the laboratory values (model_2_laboratory)
    albumin + hemoglobin +
    # random intercept for HSA
    (1 | hsanum),
  data = patient_groups[["All"]],   # model_data: the whole cohort
  family = binomial
)

# The rows reported: odds ratios for the four density categories against
# HSAs with no facility, with 95% CIs, p values and the patients used
density_effects(fit, "^density_category", exponentiate = TRUE)
```

In the code, `model_covariates("Model 3", labs = TRUE, patients = "All")` returns these 24 covariates, and `mixed_formula()` turns them into the formula. A test (`tests/test-model-example.R`) checks that the formula on this page is the one the code builds, so the example cannot drift from the code.
